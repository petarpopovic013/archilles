# Geometry extraction

Production uses `createDrawingVisionRunner` in `src/vision/pipeline.ts`, through the real Mozaik Geometry participant and its private `extract_drawing_page` tool. `createClaudeVisionRunner` remains a legacy single-response adapter for compatibility tests. The provider wire schema has fixed keys and one polygon representation, with explicit unknown sentinels; canonical Zod validation follows decoding. It returns literal annotation evidence rather than asking the model for arithmetic. Conflicting door/window observations remain `SYMBOL_AMBIGUOUS`; a later crop cannot silently erase the conflict. Both the live smoke and recognition benchmark exercise the production pipeline.

A page task has one overview/legend checkpoint, two detail calls covering four overlapping regions from the ORIGINAL, and at most one focused follow-up. Every image has an explicit affine map into canonical source coordinates. A PDF uses cropped/rotated 144-DPI coordinates, embedded text evidence and private clipped rendering. Viewer downsampling does not reduce crop resolution or establish physical scale. Model frame limits include margins and 28px patch rounding.

The user confirms drawing conventions before details. The overview is cached across that revision transition; stage caches include model, pipeline version, categories, region and settings. A task permits four logical calls, one transient retry shared across confirmation, 120 seconds per provider attempt, and between-stage expiry. Vision reserves at most $0.80 and its Mozaik controller at most $0.20. Opaque transient failures conservatively consume the reserved attempt estimate. Tokens from invalid or stale billable responses remain accounted for. An explicit reread is another task within the configured total/hourly ledger, never an automatic recursion.

`reconstructRooms` prefers the filled-wall result, and tries a narrow hatch hypothesis only for unresolved rooms (`ROOM_MASK_VARIANT`). It independently discovers omitted enclosed regions (`ROOM_UNLABELLED`); cavities inside supported rooms are review issues rather than extra rooms. It derives enclosed floor components from supported wall pixels and opening gaps. Thin visible strokes require wall anchors; furniture components are rejected as room seeds when too small. Only short collinear wall-end gaps are additionally sealed for tracing, with `WALL_GAP_REVIEW`; this does not create a door or measurement. Open connections, invalid shapes, overlaps, unsupported openings and partial coverage are exposed as report issues. A failed contour retains a visibly uncertain suggestion. Polygon vertex counts are bounded in application validation without expanding the provider grammar to hundreds of optional points.

Annotations retain literal text, position, kind, direction and visible span endpoints when available. Window/door meaning is separate from OPENING's legal element type; an unspecified opening stays UNKNOWN. Nominal size pairs never become clear-width measurements. Confirmed units and two-point calibration do not approve measurements, categories or boundaries. Physical arithmetic and all rule evaluation remain ordinary deterministic code.

Canonical `GeometryReport` and `DrawingSettings` schemas live in `src/domain/geometry.ts`. `analyzeDrawing` materializes elements and evidence, plus any explicitly supported unverified measurements from compatible adapters. The production multi-pass wire protocol retains dimensions as raw annotations; user measurement confirmation is separate. Reports expose the processed regions, issues, annotations, relationships and cumulative task usage. Private caches contain no credentials; public activity contains real allowlisted transitions, no images or prompts. Revision guards reject late results.

Boundary editing, manual creation and removal create new revisions and USER evidence. Historical snapshots are preserved. Geometry confirmation is separate from category confirmation. Explicit rereading retires AI suggestions, preserves human versions, and remaps report references for matched corrections. Dimension-only recheck does not call Vision.

Tests use original image/PDF processing with injected inference and real HTTP/Mozaik sessions. `npm run smoke:geometry` performs an explicitly paid isolated provider check; `npm run benchmark:geometry -- --plan ... --output /tmp/...` also saves private overlay images and observations. The latter can be evaluated offline with `npm run evaluate:geometry -- observations.json reference.json`. The three bundled layout families have DRAFT visual room references only. They do not establish full-plan recall, annotation accuracy, legal coverage or human-verified acceptance. See the implementation verification report in `docs/geometry-recognition-verification.md` for current measured limits.
